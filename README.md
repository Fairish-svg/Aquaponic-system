# Aquaponicsystem Project Gallery

A responsive, scrapbook-style photo gallery and photobooth editor built for the supplied green gingham / aquatic visual direction. The gallery is continuous and data-driven. Published collections are fetched from Supabase in pages; new collection events trigger a refresh. The editor keeps the original file separate and exports a PNG composited from the photo and transparent frame overlay.

## What is included

- `index.html`, `styles.css`, `app.js` — responsive site, collection browser, editor, owner upload and management interface.
- `assets/frames/*.svg` — eight individual, transparent-center frame overlays inspired by the supplied frame reference (not the entire reference sheet).
- `config.js` — browser-side Supabase project settings to fill in.
- `schema.sql` — tables, RLS policies, sequential collection IDs, owner-only RPC, and Storage policies.

## Connect the real backend

1. Create a Supabase project.
2. Open **SQL Editor** and run all of `schema.sql`.
3. In Supabase **Authentication**, create the owner account. Copy its user UUID from the user list.
4. Run `insert into public.admin_users(user_id) values ('YOUR-OWNER-USER-UUID');` in the SQL Editor. This allowlist, plus RLS policies, is the authorization check; hiding buttons is not the security boundary.
5. Disable public sign-ups after creating the owner account. Use a strong password and enable MFA if available.
6. Copy the Project URL and publishable/anon key into `config.js`.
7. Serve the folder through a static web host (for example, Netlify, Vercel, or Cloudflare Pages) or a local static server. Do not open `index.html` as a `file://` URL because browser security rules may block some functionality.
8. Open the deployed site, select **Admin corner**, sign in, and upload a multi-photo collection. Verify it appears publicly only after it is published.

The anon key is expected to be present in a browser app; **RLS is essential**. Never put a Supabase service-role key in `config.js` or any client-side file.

## Notes and operational limits

- Collection numbers are generated by a database identity sequence and remain unique; deleting a collection does not renumber others. Sequence numbers may have gaps after failed/deleted records, which is normal and safer than reusing numbers.
- The supplied reference images are design references, not real gallery photographs. The site uses a visual empty state until real collections are uploaded.
- The built-in frame assets are SVG overlays with transparent centers. The owner can upload more transparent PNG/SVG assets from the admin frame library. The overlay is stretched to the editor's preview stage; for best results, prepare frame assets for a consistent 4:3 photo-safe area.
- Original photos and frame assets use public Storage URLs to support direct downloads and browser canvas export. Public buckets mean anyone who already knows a file URL can access that file even if its collection is unpublished. For stricter privacy, change `gallery-photos` to a private bucket and implement short-lived signed URLs; update original-download and export logic accordingly. The public gallery itself is filtered by RLS to published collections.
- Collection deletion cascades photo metadata but does not automatically delete the corresponding Storage objects. Remove those objects from Storage as part of retention/cleanup. Do not treat this starter as a tested production deployment until the acceptance checks below have been run against your actual Supabase project.
- Canvas export requires image URLs to load successfully with appropriate CORS headers. If a browser blocks an asset, the editor reports an export error instead of pretending a download succeeded.

## Acceptance checklist

After backend setup, test: owner sign-in; a non-admin cannot upload; multiple photos in one collection; unique collection numbering; published collection appears in gallery; real thumbnail shown; correct collection opens; original download; frame selection updates preview; framed PNG export; original remains unchanged; refresh persistence; additional collections appear beyond the first page; iPhone Safari layout; unpublished collection absent from public gallery; exported image contains no editor UI.

This repository is an implementation starter that requires the Supabase setup above. It does not claim those deployment-level tests have already passed.
